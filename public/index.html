Before you measure anything, you need the vocabulary. These definitions are short, easy marks in the theory part of the exam.

1 · The Concept (explain like I'm 5)

Data is the raw groceries: eggs, flour, sugar. On their own they don't mean much. Information is the cake: data that has been processed until it means something.

A data structure is how you arrange the kitchen: spices on a rack, plates stacked, ingredients in labelled jars. The same groceries can be arranged in different ways, and some arrangements make cooking much faster.

Data is the quantities, characters or symbols a computer stores and operates on. In a + b, a and b are data. Data becomes information once it is processed and organised so a human can extract meaning from it.

A data type defines two things:

  1. a domain of values (for int: whole numbers);
  2. the operations allowed on those values (for int: + - * /, bitwise operations, comparisons…).

A user-defined data type is one you build yourself, usually with struct:

struct point {   // a new type called "struct point"
    int x;       // first member: an int
    int y;       // second member: another int
};

An Abstract Data Type (ADT) is the remote control: buttons labelled volume up, next channel, power. You know what each button does, not how the TV does it. The data structure is the electronics inside the TV, the actual wires that make it happen.

ADT = what to do (blueprint). Data structure = how to do it (implementation).

TermMeaningExample
ADTLogical behaviour: the operations and what they do, with no implementation details"List: insert, delete, search"

Why use ADTs? The client doesn't have to worry about how the operations are done. That gives you the three advantages of data structures from the slides: efficiency (the right structure saves time and space), reusability (many clients share one implementation) and abstraction (clients ignore internal details).

When you pick a data structure for an ADT you compare: (1) the space it needs, (2) the time each basic operation takes, (3) how complex it is to program.

Explain in one sentence exam style

Explain the difference between an ADT and a data structure, giving one example of each. Then classify an array and a linked list as static/dynamic and say one advantage and one disadvantage of each.

An ADT specifies what operations are possible and how they behave without saying how they are implemented (e.g. a List ADT with insert, delete, search). A data structure is a concrete implementation of an ADT in memory (e.g. a singly linked list using struct node and pointers).

  • Array: static. Advantage: O(1) access by index. Disadvantage: fixed size, and insert/delete at the start or middle costs O(n) because of shifting.
  • Linked list: dynamic. Advantage: grows and shrinks at run time, and inserting/deleting just relinks pointers (no shifting). Disadvantage: no direct indexing, so reaching the k-th element costs O(n).

ADT = what (blueprint). Data structure = how (implementation). Linear vs non-linear depends on the shape. Static vs dynamic depends on when the memory is allocated.

Why don't we just time programs with a stopwatch? Because the answer changes with the machine. Instead we count steps as a function of the input size n.

1 · The Concept (explain like I'm 5)

You want to compare two pizza delivery drivers. Timing them one evening is unfair: one had traffic, one had a faster scooter. A fairer question is: "How many streets does each driver cross for an order n streets away?" That number doesn't depend on the scooter. That's what f(n) is: the number of basic steps for an input of size n.

The slides list the problems with measuring exact running time on a real machine:

  • For some input sizes structure A wins, for others structure B wins.
  • On one machine A wins, on another machine B wins.

So we count operations instead, and write the count as a function f(n) (or T(n)) of the input size n.

TD B3 · Two consecutive loops

Derive T(n) under the statement-count model, then state Θ(·). Why are the costs of the two loops added rather than multiplied?

int f(int n) {
    int x = 0;
    for (int i = 0; i < n; i++)
        x++;
    for (int j = 0; j < n; j++)
        x += 2;
    return x;
}
int f(int n) {
    int x = 0;                    // 1 statement, runs once                -> 1
    for (int i = 0; i < n; i++)   // loop 1 runs its body n times
        x++;                      // 1 statement x n                       -> n
    for (int j = 0; j < n; j++)   // loop 2 starts AFTER loop 1 finishes
        x += 2;                   // 1 statement x n                       -> n
    return x;                     // 1 statement, runs once                -> 1
}

T(n) = 1 + n + n + 1 = 2n + 2 ∈ Θ(n). (If you also count each loop header as a statement executed n + 1 times, you get 4n + 4. Still Θ(n).)

Why add? The loops are consecutive: the second one starts only when the first has completely finished, so the costs pile up one after the other (n + n). You multiply only when one loop is inside another, because then the inner loop runs once for each outer iteration.

Washing the dishes and then drying them: 10 min + 10 min. Checking every page of 10 books where each book has 10 pages: 10 × 10.

TD B4 · Closed-form replacement

Compare the two functions. For each, derive an operation count under one clearly stated model and give the complexity. Explain the algorithmic reason for the difference.

int sum1(int n) {
    int s = 0;
    for (int i = 1; i <= n; i++)
        s += i;
    return s;
}

int sum2(int n) {
    return n * (n + 1) / 2;
}

Model: primitive operations, every operator counts 1 (+= counts 1, return counts 1).

int sum1(int n) {
    int s = 0;                      // 1 assignment                   -> 1
    for (int i = 1; i <= n; i++)    // i = 1 -> 1 | i <= n -> n+1 | i++ -> n
        s += i;                     // 1 compound assignment x n      -> n
    return s;                       // 1                              -> 1
}                                   // T1(n) = 1 + 1 + (n+1) + n + n + 1 = 3n + 4

int sum2(int n) {
    return n * (n + 1) / 2;         // +, *, / and return = 4 operations, ALWAYS
}                                   // T2(n) = 4

sum1 ∈ Θ(n) (linear), sum2 ∈ Θ(1) (constant).

Why the difference? sum1 computes the sum by brute force, visiting all n numbers. sum2 uses Gauss's closed-form formula 1 + 2 + … + n = n(n+1)/2, so the work no longer depends on n. Replacing a loop by mathematics is one of the most powerful optimisations.

The slides do the same example with statement counting: f(n) = n + 4 → O(n) with c = 2, n₀ = 4, and the optimised version f(n) = 4 → O(1) with c = 5, n₀ = 1.

Count how many times each line executes. Loop tests run n + 1 times. Consecutive blocks add; nested blocks multiply. Constant factors never change the final class.

Once you have f(n), you only care about how it grows when n gets huge. This level teaches you to rank functions, find the dominant term, and write the formal proofs the exam asks for.

1 · The Concept (explain like I'm 5)

Picture runners on a track that never ends. One walks at a steady speed (n). One gets faster every lap (n²). One doubles its speed every lap (2ⁿ). At the start the walker might even be ahead, but after enough laps the doubler is so far ahead that the others look like they're standing still. Big O only cares about who wins the long race, not who leads after the first lap.

In f(n) = 5n² + 6n + 12, the 5n² is an elephant and 6n + 12 are mice. Weigh them together on a scale and the mice don't matter. So f(n) ≈ 5n², and we write O(n²).

2 · The Syntax: the formal definitions

Big O is a ceiling: f never goes above c·g (eventually). Big Omega (Ω) is a floor: f never goes below c·g. Theta (Θ) is a sandwich: f is stuck between two copies of g, so it grows exactly like g.

NotationDefinition (there exist constants…)Meaning
f(n) ∈ O(g(n))c > 0, n₀ > 0 such that f(n) ≤ c·g(n) for all n ≥ n₀upper bound: grows no faster than g (worst case)
f(n) ∈ Ω(g(n))c > 0, n₀ > 0 such that f(n) ≥ c·g(n) for all n ≥ n₀lower bound: grows at least as fast as g
f(n) ∈ Θ(g(n))c₁, c₂ > 0, n₀ such that c₁·g(n) ≤ f(n) ≤ c₂·g(n) for all n ≥ n₀tight bound: O and Ω at the same time
f(n) ∈ o(g(n))lim f(n)/g(n) = 0strictly slower than g (like "<")
f(n) ∈ ω(g(n))lim f(n)/g(n) = ∞strictly faster than g (like ">")

Think of them as comparisons between growth rates: O ≈ ≤, Ω ≈ ≥, Θ ≈ =, o ≈ <, ω ≈ >.

Recipe for an O proof (the slides' Example 2, f(n) = 4n + 3):

  1. Write what you need: 4n + 3 ≤ c·n.
  2. Pick c a bit bigger than the leading coefficient: c = 5.
  3. Solve: 4n + 3 ≤ 5n ⇔ 3 ≤ n. So n₀ = 3.
  4. Conclude: f(n) ≤ 5n for all n ≥ 3, hence f(n) ∈ O(n). ∎

For n ≥ 1, every lower power is ≤ the top power: n ≤ n², 1 ≤ n². So replace every term by the top power: 6n² + 3n + 2 ≤ 6n² + 3n² + 2n² = 11n². Instant c = 11, n₀ = 1.

TD A1 · Rank the growth rates

Arrange from slowest to fastest growth, grouping functions with the same asymptotic growth:

1, log₂ n, log₁₀ n, √n, n, n log₂ n, n², n³, 2ⁿ, 3ⁿ, n!, nⁿ

1 < { log₂ n , log₁₀ n } < √n < n < n log₂ n < n² < n³ < 2ⁿ < 3ⁿ < n! < nⁿ

Grouped together: log₂ n and log₁₀ n (same class Θ(log n)).

Why ignore the base? By the change-of-base formula, log₂ n = log₁₀ n / log₁₀ 2 ≈ 3.32 · log₁₀ n. Two logs with different bases differ only by a constant factor, and asymptotic notation ignores constants.

Careful: 2ⁿ and 3ⁿ are not in the same class. 3ⁿ / 2ⁿ = (1.5)ⁿ → ∞, which is not a constant. The base matters for exponentials, but not for logarithms.

TD A3 · Formal O, Ω and Θ

  1. Prove 4n + 3 ∈ O(n) by giving one valid pair (c, n₀).
  2. Prove 4n² + 100n + 500 ∈ Ω(n²).
  3. Prove 6n² + 3n + 2 ∈ Θ(n²) by constructing both bounds.
  4. Explain why n³ − 100n² ∉ O(n²).

(a) Take c = 5: 4n + 3 ≤ 5n ⇔ n ≥ 3. So with c = 5, n₀ = 3, 4n + 3 ≤ 5n for all n ≥ n₀. ∎ (Also valid: c = 7, n₀ = 1, because 4n + 3 ≤ 4n + 3n = 7n for n ≥ 1.)

(b) For n ≥ 1, 100n + 500 > 0, so 4n² + 100n + 500 ≥ 4n². With c = 4, n₀ = 1, f(n) ≥ c·n² for all n ≥ n₀. ∎

(c) Lower bound: 6n² + 3n + 2 ≥ 6n² for n ≥ 1 → c₁ = 6. Upper bound: for n ≥ 1, 3n ≤ 3n² and 2 ≤ 2n², so 6n² + 3n + 2 ≤ 11n² → c₂ = 11. Hence 6n² ≤ f(n) ≤ 11n² for all n ≥ 1 (c₁ = 6, c₂ = 11, n₀ = 1), so f(n) ∈ Θ(n²). ∎

(d) Proof by contradiction. Suppose constants c, n₀ exist with n³ − 100n² ≤ c·n² for all n ≥ n₀. Divide by n² (n > 0): n − 100 ≤ c, i.e. n ≤ c + 100. That must hold for every n ≥ n₀, but it fails for n = max(n₀, c + 101). Contradiction, so n³ − 100n² ∉ O(n²). Intuitively, the n³ term eventually wins no matter how big c is.

TD A4 · True or false?

  1. n ∈ O(n²)
  2. n² ∈ O(n)
  3. 5n² + 2n ∈ Θ(n²)
  4. log₂ n ∈ Θ(log₁₀ n)
  5. n³ ∈ Ω(n²)
  6. n² ∈ o(n³)
  7. n³ ∈ ω(n²)
  1. True. n ≤ 1·n² for n ≥ 1. O is only a ceiling, and a loose ceiling is still a ceiling.
  2. False. n² ≤ c·n would mean n ≤ c for all large n. Impossible.
  3. True. 5n² ≤ 5n² + 2n ≤ 7n² for n ≥ 1.
  4. True. log₂ n = (1/log₁₀ 2)·log₁₀ n ≈ 3.32·log₁₀ n: a constant multiple.
  5. True. n³ ≥ 1·n² for n ≥ 1.
  6. True. lim n²/n³ = lim 1/n = 0.
  7. True. lim n³/n² = lim n = ∞.

Lecture exercise · Dominant term and Big O

Classify each expression in Big O:

  1. 48n⁴ + 16n² + log₈ n + 2n
  2. n²/2 + 3000n
  3. 0.0001n² + 10000n − (6n⁵ + 3)/n⁴
  1. O(n⁴): 48n⁴ dominates.
  2. O(n²): even divided by 2 and against a big 3000n, n² wins for large n (here from n > 6000).
  3. Simplify first: (6n⁵ + 3)/n⁴ = 6n + 3/n⁴, which is just O(n). So the expression is 0.0001n² + 9994n − 3/n⁴ → O(n²). Tiny coefficients don't matter.

Lecture exercise · Which algorithm is better?

Algorithm A does a task in time n³ + 300n. Algorithm B does the same task in 30n² + 1000. (i) Give the Big O of each. (ii) Which is more efficient?

(i) A ∈ O(n³), B ∈ O(n²).

(ii) B is more efficient for large inputs, since n² grows slower than n³. Bonus insight: at n = 10 both cost exactly 4000 steps (1000 + 3000 = 3000 + 1000). For n < 10, A is slightly faster; for n > 10, B wins, and the gap keeps growing. Asymptotic analysis answers the "large n" question.

Keep the dominant term and drop its coefficient. For proofs, write the inequality, choose c, solve for n₀, conclude. O = ceiling, Ω = floor, Θ = sandwich. The log base doesn't matter; the exponential base does.

This is the skill the exam rewards most: look at a loop, know how many times it runs. Learn six patterns and you can read almost any code.

1 · The Concept (explain like I'm 5)

i++ is climbing a staircase one step at a time: 100 stairs = 100 steps (linear).
i += 3 is taking three stairs at once: about 33 steps. Still proportional to the stairs, so still linear.
i *= 2 is a magic elevator that doubles your floor each ride: 1 → 2 → 4 → 8 → … → 1024 in only 10 rides. That's logarithmic: log₂ n rides.

Looking for "Martin" in a 1000-page phone book: open it in the middle, throw away the wrong half, repeat. 1000 → 500 → 250 → … → 1 takes about 10 halvings. Every time you cut the problem by a fraction, you get log n.

Nested loops are like a clock. For every single tick of the hour hand (outer loop), the minute hand goes all the way round (inner loop). 12 hours × 60 minutes = 720 ticks. That's why nested loops multiply.

Where does log come from? In for (i = 1; i <= n; i *= 2), after k iterations i = 2ᵏ. The loop stops when 2ᵏ > n, i.e. after k = ⌊log₂ n⌋ + 1 iterations.

iteration:  1    2    3    4    5   ...   k
value of i: 2^0  2^1  2^2  2^3  2^4 ...   2^(k-1) <= n   ->  k - 1 = log2(n)  ->  k = log2(n) + 1

The four combination rules

  • Consecutive blocks: add, then keep the biggest. n + n² + log n → Θ(n²).
  • Nested loops: multiply the counts if they are independent; use a summation if the inner bound depends on the outer variable.
  • if / else: T = T(condition) + max(T(if), T(else)). Only one branch runs per call.
  • Always look at the slowest part.

Derive the iteration count of each loop and its Θ bound.

i = 0;                // start at 0

    i += 3;           // jump 3 stairs: after k iterations, i = 3k
}                     // stops when 3k >= n  ->  k = ceil(n/3) iterations  ->  Theta(n)

i = 1;                // start at 1
while (i < n) {       // runs while i takes the values 1, 3, 9, 27, ..., each one < n
    i *= 3;           // magic elevator x3: after k iterations, i = 3^k
}                     // stops when 3^k >= n  ->  k = ceil(log3 n) iterations  ->  Theta(log n)

int g(int n) {

        return n * n;                 // if-branch: one multiplication -> O(1)
    } else {
        int s = 0;                    // O(1)
        for (int i = 0; i < n; i++)   // runs n times
            s += i;                   // O(1) each -> O(n) total
        return s;                     // O(1)
    }                                 // else-branch: O(n)
}

When the inner loop's bound depends on the outer variable, you can't just multiply. You add up the work of each outer iteration with a Σ. Five formulas are enough for every exercise in the TD.

1 · The Concept (explain like I'm 5)

A child gets 1 candle on their 1st birthday, 2 on their 2nd, 3 on their 3rd… How many candles in total by birthday n? 1 + 2 + … + n. That's exactly a loop where the inner part runs i times. Young Gauss noticed you can pair them up: (1 + n) + (2 + n−1) + … gives n/2 pairs worth n + 1 each, so the total is n(n+1)/2. That's about n²/2, so Θ(n²).

Put 1 grain on the first square, 2 on the next, 4, 8, 16… The last square alone holds more than all the previous squares together (1 + 2 + 4 + 8 = 15 < 16). A doubling sum is basically just twice its last term. That's why 1 + 2 + 4 + … + n = Θ(n), not n log n.

TD D1 · Geometric-series loop

for (int i = 1; i <= n; i *= 2) {
    for (int j = 0; j < i; j++) {
        count++;
    }
}
  1. List the inner-loop counts for the first five outer iterations.
  2. Write the total as 1 + 2 + 4 + ⋯ up to the largest power of two ≤ n.
  3. Use the geometric-series formula to show the total is Θ(n), not Θ(n log n).
  1. i = 1, 2, 4, 8, 16 → inner counts 1, 2, 4, 8, 16.
  2. Let m = ⌊log₂ n⌋ (so 2ᵐ is the largest power of two ≤ n). T(n) = 1 + 2 + 4 + ⋯ + 2ᵐ = Σk=0m 2ᵏ.
  3. Geometric formula: T(n) = 2m+1 − 1. Since 2ᵐ ≤ n < 2m+1: upper T(n) = 2·2ᵐ − 1 ≤ 2n − 1, and lower T(n) = 2m+1 − 1 ≥ n (because 2m+1 > n, so 2m+1 ≥ n + 1). So n ≤ T(n) ≤ 2n − 1, hence T(n) ∈ Θ(n).

The naive reasoning "outer log n × inner up to n = n log n" only gives an upper bound. It pretends every inner loop costs n, when most of them are tiny (1, 2, 4…). Only the last one costs about n, and all the others together cost less than it. Big O allows n log n; tight Θ is n.

TD D2 · Logarithmic inner loop, linear outer loop

for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= i; j *= 2) {
        count++;
    }
}

Write the total as Σi=1n (⌊log₂ i⌋ + 1) and find a tight bound with a bounding argument.

For a fixed i, j = 1, 2, 4, … ≤ i runs ⌊log₂ i⌋ + 1 times, so T(n) = Σi=1n (⌊log₂ i⌋ + 1).

Upper bound: each term ≤ log₂ n + 1, and there are n terms → T(n) ≤ n(log₂ n + 1) ∈ O(n log n).

Lower bound: keep only the last half of the terms, i ≥ n/2 (about n/2 terms). Each of them is ≥ log₂(n/2) = log₂ n − 1. So T(n) ≥ (n/2)(log₂ n − 1) ∈ Ω(n log n).

Both bounds match: T(n) ∈ Θ(n log n).

For a lower bound on a sum of growing terms, throw away the small first half. The remaining half has n/2 terms, each at least as big as the middle term.

Enter World 2 · Linked Lists →

Two ways to keep a list of things in memory. Each is fast at what the other is slow at. Knowing why is a classic exam question.

1 · The Concept (explain like I'm 5)

An array is a row of lockers glued side by side and numbered 0, 1, 2… To open locker 57 you walk straight to it: address = start + 57 × locker size. That's O(1) access. But the row has a fixed length, and to squeeze a new item in at the front, everyone has to shift one locker to the right: O(n).

A linked list is a treasure hunt. Each clue (node) holds a prize (data) and a note saying where the next clue is hidden (next pointer). The clues can be anywhere in town (anywhere in RAM). Adding a clue is easy: just rewrite one note, with no shifting. But to reach clue 57 you must follow clues 1, 2, 3… one by one: O(n) access. You only ever hold the location of the first clue: the head. The last clue says "THE END" (NULL).

Exam question · Why does a list beat an array at the front?

Explain, with complexities, why inserting at the beginning of an array of n elements costs O(n) while it costs O(1) in a linked list. Then give one disadvantage of linked lists.

In an array, elements are stored contiguously. To put a new element at index 0, every existing element must move one position to the right to free the slot, which is n shifts: O(n) (one shift = one unit of time, as in the slides). In a linked list, nodes are linked by pointers, so we only allocate a node, set newNode->next = head and head = newNode. That's a fixed number of operations whatever n is: O(1).

Disadvantage: no random access. Reading the k-th element requires following k pointers (O(n)). Each node also wastes memory on its pointer.

Array = numbered lockers (O(1) access, O(n) shifting). List = treasure hunt (O(1) relinking, O(n) access). head = the first clue, NULL = the end.

Pointers scare everyone at first. In reality there are only five symbols to master: &, *, ., -> and malloc/free. Master them here and linked lists become easy.

1 · The Concept (explain like I'm 5)

Memory is a long street of houses. Each house has an address (like 0x1000) and something inside (a value, like 5).

  • A normal variable int severity = 5; is a house with 5 inside.
  • &severity means "what's the address of that house?" → 0x1000.
  • A pointer int *p is a sticky note with an address written on it. p = &severity; writes 0x1000 on the note.
  • *p means "go to the address on the note and look inside": you find 5. *p = 8; means "go there and replace what's inside with 8", so severity is now 8.
        p                         severity
   +----------+  points to   +-----------+
   |  0x1000  | -----------> |     5     |    address 0x1000
   +----------+              +-----------+
   p == &severity            *p == severity == 5

A struct is a paper form with several boxes: ID, severity, code. If you hold the form itself, you read a box with a dot: event1.severity. If you only hold a sticky note with the form's address, you first go there, then read the box: ptr->severity, which is exactly (*ptr).severity.

malloc(sizeof(struct node)) asks the system: "rent me a storage unit big enough for one node." It gives you back the unit's address, or NULL if nothing is free. That memory lives on the heap: it stays alive after the function returns, until you give the key back with free(). Forget to free it and you have a memory leak. Use it after freeing and you have a dangling pointer.

Pass by value vs pass by reference:

Pass by value gives the function a photocopy of your document. It can scribble on it all it wants; your original is untouched. Pass by reference (passing a pointer) gives the function the address of your house. It walks in and changes the real thing.

1 · The Concept (explain like I'm 5)

A linked list is a conga line where each dancer holds the shoulder of the person in front. You (the head pointer) only know the first dancer. To count the dancers you walk along the line, tapping each shoulder and following the hand to the next one, until you reach a dancer whose hand holds nobody (NULL). That walk is called traversal, and it always takes n steps: O(n).

If you move head itself to walk the list, you lose the first dancer forever. Nothing points to them any more, so that memory is leaked. Always walk with a copy: struct node *current = head;

2 · The Syntax / Example

Building 23 → 54 → 3 by hand (the slides' "Method 2", with no unnecessary pointers):

struct node {
    int data;
    struct node *next;
};

int main(void) {

    head->data = 23;                  // A.data = 23
    head->next = NULL;                // for now A is the last node

    struct node *current = malloc(sizeof(struct node)); // node B rented, current = its address
    current->data = 54;               // B.data = 54
    current->next = NULL;             // B is the last node
    head->next = current;             // A -> B (link A to B)

    current = malloc(sizeof(struct node)); // REUSE current for node C (B is still reachable via head->next)
    current->data = 3;                // C.data = 3
    current->next = NULL;             // C is the last node
    head->next->next = current;       // B -> C, so we have head -> 23 -> 54 -> 3 -> NULL
    return 0;
}

Writing head = malloc(...) a second time makes head point to the new node, and the first node is lost. Nothing holds its address any more. Always link a new node before moving the only pointer to the old one.

With addresses head = 1000, second node = 2000, third = 4000: head->next = 2000, head->next->next = 4000, head->next->next->next = NULL.

Chapter 2 · Sort the list (swap data)

Sort the list by ascending eventID by swapping data between nodes (as in the lecture). Give its complexity.

void sortList(struct node *head) {
    if (head == NULL || head->next == NULL)   // 0 or 1 node: already sorted
        return;

    struct node *current, *index;
    int tmp;

    for (current = head; current != NULL; current = current->next) {          // each node...
        for (index = current->next; index != NULL; index = index->next) {     // ...vs every node after it
            if (current->eventID > index->eventID) {   // wrong order?
                tmp = current->eventID;                // swap the IDs
                current->eventID = index->eventID;
                index->eventID = tmp;
                tmp = current->severity;               // swap the severities too, so they stay paired
                current->severity = index->severity;
                index->severity = tmp;
            }
        }
    }
}

The inner loop runs (n−1) + (n−2) + … + 1 = n(n−1)/2 times → O(n²). The nodes don't move; only their contents are swapped. This is a selection-style exchange sort.

Lecture question · Linking nodes

Three stack nodes a, b, c hold 1, 2, 3, with a.next = &b; b.next = &c; c.next = NULL;. What are a.next->data and a.next->next->data?

a.next is the address of b, so a.next->data = 2. a.next->next is the address of c, so a.next->next->data = 3. Note the mix: a is a struct (use .), a.next is a pointer (use ->).

Walk with a copy (current = head), never with head. The loop body must end with current = current->next. Visiting every node is O(n).

Three insertions, one secret: connect the new node first, then redirect the old link. Do it in the wrong order and you lose the rest of the list.

Deleting means two separate jobs: unlink the node so the list skips it, then free its memory. Keep a pointer to the victim before you unlink it, or you can't free it.

1 · The Concept (explain like I'm 5)

Sara wants to leave the chain Ali – Sara – Omar. First Ali grabs Omar's hand (ali->next = sara->next), so the chain is whole again. Then Sara goes home (free(sara)). If Sara left first, Ali would be holding nothing and Omar's whole side would be lost.

And you need to know who's before Sara (Ali). In a singly list you can't walk backwards, so while walking you keep two fingers: previous and current.

Leak: you unlink a node but never free it. That memory is lost until the program ends. Dangling pointer: you free(temp) and then use temp->next. Undefined behaviour. Read everything you need before freeing, and set the pointer to NULL afterwards (the whiteboard's temp = NULL;).

Two upgrades to the singly list. Doubly lists can walk backwards; circular lists have no end. Same ideas as before, just more pointers to fix.

1 · The Concept (explain like I'm 5)

A singly list is a line of people holding the shoulder in front: you can only go forward. A doubly linked list is a train where every wagon is coupled to the wagon in front (next) and the wagon behind (prev). You can walk both ways, and any wagon knows its neighbours. The cost: every insertion or deletion has to fix both couplings.

A circular list is King Arthur's round table: after the last knight comes the first again. There is no NULL. Instead of a head we keep a pointer to the last knight, because from the last you reach the first in one step (last->next). So you can add someone at the front or the back in O(1) without walking around the table.

DOUBLY:    NULL <- [prev| 4 |next] <-> [prev| 5 |next] <-> [prev| 6 |next] -> NULL
                    ^head

CIRCULAR:  +--> [10|next] --> [3|next] --> [8|next] --+
           |                                 ^last    |
           +------------------------------------------+     last->next == first node

Write insertEnd, delete_head_node and deleteLast for a doubly list.

void insertEnd(struct Node **head, int data) {           // O(n): walk to the end
    struct Node *newNode = malloc(sizeof(struct Node));
    if (newNode == NULL) return;
    newNode->data = data;
    newNode->next = NULL;                  // it will be the last
    if (*head == NULL) {                   // empty list: new node is everything
        newNode->prev = NULL;
        *head = newNode;
        return;
    }
    struct Node *temp = *head;
    while (temp->next != NULL)             // stop ON the last node
        temp = temp->next;
    temp->next = newNode;                  // old last -> new
    newNode->prev = temp;                  // old last <- new
}

void delete_head_node(struct Node **head) {               // O(1)
    if (*head == NULL) return;             // empty: nothing to do
    struct Node *node_to_del = *head;      // remember the victim
    *head = node_to_del->next;             // head moves to the 2nd node
    if (*head != NULL)                     // if the list isn't now empty...
        (*head)->prev = NULL;              // ...the new first node has no predecessor
    free(node_to_del);
}

void deleteLast(struct Node **head) {                     // O(n): walk to the end
    if (*head == NULL) return;
    struct Node *temp = *head;
    while (temp->next != NULL)             // go to the last node
        temp = temp->next;
    if (temp->prev == NULL)                // it was the only node
        *head = NULL;
    else
        temp->prev->next = NULL;           // predecessor becomes the end: no need for "previous"!
    free(temp);
}

Doubly advantage: in deleteLast we don't need a trailing previous pointer, because temp->prev gives it for free. To delete a node you already hold (deleteAfter, or deleting the node itself), you just do node->prev->next = node->next; node->next->prev = node->prev; (checking each for NULL): O(1).

Write void reverse(struct node **head), which reverses a singly linked list in place (no new nodes, no array). 101 → 102 → 103 becomes 103 → 102 → 101. Give its time and extra-space complexity.

void reverse(struct node **head) {
    struct node *prev = NULL;        // the reversed part so far (initially empty)
    struct node *current = *head;    // the node we are turning around
    struct node *next = NULL;        // a bookmark so we don't lose the rest of the list

    while (current != NULL) {
        next = current->next;        // 1. bookmark the rest of the list
        current->next = prev;        // 2. turn this node's arrow backwards
        prev = current;              // 3. the reversed part now starts at current
        current = next;              // 4. move on to the bookmarked rest
    }
    *head = prev;                    // prev is the old last node = the new first node
}
start:   prev=NULL   current=101 -> 102 -> 103 -> NULL
step 1:  NULL <- 101   prev=101   current=102 -> 103
step 2:  NULL <- 101 <- 102   prev=102   current=103
step 3:  NULL <- 101 <- 102 <- 103   prev=103   current=NULL  -> stop, head = 103

Time O(n) (each node is visited once), extra space O(1) (three pointers). Works for empty and one-node lists with no special case.

Marking: 1 pt for the bookmark of next, 1.5 for the arrow reversal, 1 for the loop/advance, 0.5 for updating *head, 1 for the complexity.

Advanced lists 4 pts

(a) 2 pts: Write int countCircular(struct Node *last) for a circular singly list referenced by its last node, and explain why while (p != NULL) can't be used.

(b) 2 pts: In a doubly linked list, write void deleteNode(struct Node **head, struct Node *del), which deletes the node del that you already hold. What is its complexity, and why is it better than in a singly list?

int countCircular(struct Node *last) {
    if (last == NULL) return 0;          // empty list
    int count = 0;
    struct Node *p = last->next;         // first node
    do {
        count++;
        p = p->next;
    } while (p != last->next);           // back at the first node: one full lap done
    return count;
}

A circular list has no NULL: the last node points back to the first, so p != NULL stays true forever (an infinite loop). We stop when we return to the starting node.

void deleteNode(struct Node **head, struct Node *del) {
    if (*head == NULL || del == NULL) return;
    if (*head == del)                    // deleting the first node
        *head = del->next;               //   head moves forward
    if (del->next != NULL)               // there is a successor
        del->next->prev = del->prev;     //   successor skips back over del
    if (del->prev != NULL)               // there is a predecessor
        del->prev->next = del->next;     //   predecessor skips forward over del
    free(del);
}

O(1): del->prev gives the predecessor directly. In a singly list you'd have to traverse from the head to find the predecessor: O(n).
