# AGENTS.md

## What this is
A static, gamified revision hub for the "Advanced Algorithms" university module (complexity and linked lists in C). Everything lives in **`public/index.html`**: content, CSS and JS. There is no framework and no build step. `netlify.toml` publishes `public/`.

## Architecture (inside `public/index.html`)
- **Skeleton (from the user, keep it intact):** the sidebar, section index pages, article headers, solution toggles, pager and hash router are all generated by the first `<script>` from the markup:
  - `<section class="view" id=… data-a=1..4 data-title data-unit data-desc>` = one sidebar group (data-a picks the accent colour; `4` was added for the Cheat Codes).
  - `<article id=… data-kicker data-title data-meta>` = one page. **Always fill all three.** Routing is `#article-id`.
  - `<div class="ex">` = exercise card (auto-numbered); `<div class="solution" data-label="…">` = hidden answer (the button is added automatically).
  - Components: `.lead`, `.callout` (`.tip`, `.warn`, `data-t` = title), `.formula`, `.tw>table`, `pre>code`, `.opts`.
- **Game layer (second `<script>` + CSS block appended at the end of `<style>`):**
  - An article with `data-xp` counts as a level: a "claim XP" box is injected before its pager. Progress is saved in `localStorage` under `aa-cleared`.
  - `ul.opts.quiz` with `data-ok` on the correct `<li>` = a clickable quiz.
  - `<div class="timer" data-min="90">` = exam countdown.
  - `<div id="playground">` (Level 8) = linked-list visualiser.
  - Use `class="go"` for in-content CTA links. **Never** use `.sol-btn` on links, because the skeleton's click handler would treat it as a solution toggle.
- Images: `public/img/*.jpeg` (whiteboard photos), referenced via `/.netlify/images?url=/img/…&w=720&fm=webp` with an `onerror` fallback to the raw file.

## Conventions
- Each level follows the user-mandated structure: 1 · Concept (ELI5 analogy in a `.callout`), 2 · Syntax/Example, 3 · Challenge (`.ex`), 4 · Solution (inside `.solution`) with C code **commented on almost every line** plus a plain-words Big O.
- C code inside `<pre><code>` must be HTML-escaped (`&lt;`, `&gt;`, `&amp;`). In inline `<code>` write `&amp;` / `&lt;` explicitly.
- Math is plain Unicode/HTML (`n²`, `Σ<sub>i=1</sub><sup>n</sup>`, `⌊log₂ n⌋`). No MathJax.
- Lab code uses `struct node { int eventID; int severity; struct node *next; }` and `struct node **head` for functions that change the head. Circular-list code uses a `last` pointer and returns the new `last` (matching the whiteboard sessions).
- Tone: encouraging, beginner-friendly, exam-focused. English, with French exam vocabulary where useful (TD, examen blanc).

## Extending
New syllabus chapters (stacks/queues, trees, sorting, graphs) should become new `<section class="view">` worlds with `data-xp` levels in the same four-step format. Bump `data-a` colours if adding more than four sections.
